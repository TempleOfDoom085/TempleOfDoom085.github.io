Securing AI systems.

02 — Defence in depth

No single control holds.

Prompt injection can't be fully solved inside the model, so the goal is containment: assume the model will sometimes be manipulated and make sure that, when it is, nothing important happens. Each layer catches what the one before it missed.

Layer 1
Govern
AI inventory & AI-BOMData classificationVendor & model reviewAcceptable-use policyRisk register

You can't secure AI you don't know is running. Visibility into every model, agent, dataset and integration comes first.

Layer 2
Input
Isolate & label untrusted contentInjection classifiersNormalise encodingsStrip hidden textRate & size limits

Separate instructions from data before it reaches the model, and flag content that is trying to act like instructions.

Layer 3
Model & prompt
No secrets in promptsLeast-capable modelExplicit trust boundariesStructured outputs

Treat the system prompt as public. It shapes behaviour; it is not a security boundary.

Layer 4
Action
Least-privilege toolsUser-scoped credentialsAuthorisation in codeHuman approval for irreversible actionsSpend & rate caps

The blast radius of a successful injection is decided here. An agent that can only read can't wire money.

Layer 5
Output
Encode before renderingRestrict links & imagesSchema validationPII & secret scanningSandbox generated code

Treat model output like any untrusted user input before it reaches a browser, shell, database or customer.

Layer 6
Monitor
Full prompt & tool-call logsAnomaly detectionContinuous red-teamingIncident playbooksKill switch

Runtime visibility turns a silent compromise into an alert — and lets you prove what an agent did, and why.

03 — Defender's playbook

Prompt injection, defended.

The main classes of prompt-injection risk, written for the people defending against them: how each works at a conceptual level, what to look for, what actually mitigates it, and how to test your own system safely.

Testing safely: only test systems you own or are authorised to assess. Use a harmless canary — a unique, meaningless token you ask the model to output or a tool call to a no-op endpoint — so success is unmistakable and nothing real is touched. Run tests in a staging environment with logging on, and re-run them on every model, prompt or tool change.
